Abstract

A key challenge in deep reinforcement learning for multi-task settings is performing long-horizon tasks consecutively and reaching the final goal through a single trained model. The objective of this research is to define multiple consecutive tasks for non-prehensile manipulation and achieve the final goal, which is hovering a thrown ball at a specific position. Separate but similar rewards are designed for each task to facilitate a smooth transition from one task to the next. The agents are trained in parallel with dynamic entropy levels, and the tasks are defined as catching, stabilizing, hovering, carrying to a target point, and hovering again. The results indicated that the agents can perform multiple tasks through one network for all the tasks and complete them consecutively to reach the final target point.

🎯 Key Contributions

  • ✅ Real-time learning-based catching with minimal delay
  • ✅ Sim-to-real transfer with adaptive control
  • ✅ Multi-task learning using a single neural network
  • ✅ Experimental validation on the KUKA iiwa robot
  • ✅ Novel reward design for smooth task transitions

⚠️ Challenges & Solutions

🎯 Challenge 1: Real-Time Latency

Catching a moving object requires predictions with minimal delay. Initial network inference took 150ms, which was too slow for dynamic object tracking.

✓ Solution: Optimized the neural network architecture by reducing layer complexity and implementing inference optimization techniques. Achieved ~50ms latency on embedded systems through quantization and model pruning.

🔄 Challenge 2: Sim-to-Real Transfer Gap

The trained policy in simulation performed well but struggled when deployed on the real KUKA robot due to differences in physics simulation, sensor noise, and actuator dynamics.

✓ Solution: Implemented domain randomization during training, including random friction coefficients, object masses, and camera noise. Fine-tuned the policy on real robot data for 500 additional episodes to adapt to real-world conditions.

🎓 Challenge 3: Multi-Task Learning Convergence

Training a single network for five consecutive tasks caused the network to forget earlier tasks (catastrophic forgetting) and struggle with smooth task transitions.

✓ Solution: Designed separate but complementary reward functions for each task with smooth transition criteria. Used curriculum learning to progressively introduce task complexity, and employed dynamic entropy coefficients to balance exploration and exploitation across tasks.

⚡ Challenge 4: Ball Tracking and Detection

The OptiTRack system required 10+ calibrated cameras and was sensitive to lighting conditions. Ball tracking sometimes failed when the object moved too fast or encountered occlusions.

✓ Solution: Implemented a hybrid approach combining OptiTRack with a learned vision model for trajectory prediction. Added redundancy with multiple detection methods and developed a Kalman filter for robust ball position estimation even during temporary occlusions.

📊 Challenge 5: Reward Shaping Complexity

Finding appropriate reward weights for multiple objectives (catching accuracy, stability, position tracking, etc.) was difficult and required extensive hyperparameter tuning.

✓ Solution: Used multi-objective reinforcement learning with automatic reward weight optimization. Implemented a progressive reward scheme where weights shift based on task progress, and conducted systematic ablation studies to understand each component's contribution.

🤖 Challenge 6: Robot Safety and Hardware Constraints

The robot's joint limits, velocity constraints, and safety requirements sometimes conflicted with optimal catching trajectories, and hardware failures could occur during learning.

✓ Solution: Built safety constraints directly into the action space by clipping velocities and enforcing joint limits. Trained exclusively in simulation first with realistic constraints, and implemented a kill-switch mechanism with timeout protection for real-world deployment.

🔧 Technical Details

Learning Approach

We employ deep reinforcement learning with the following components:

  • Algorithm: Proximal Policy Optimization (PPO)
  • Network Architecture: 1-layer LSTM + 4-layer fully connected neural network
  • State Space: 44-dimensional (position, velocity, orientation)
  • Action Space: 7-dimensional robot joint velocities
  • Training Time: ~50,000 episodes for all tasks

Reward Function Design

The reward function is carefully structured to guide the agent through multiple sequential tasks while maintaining stability and minimizing undesired behaviors:

Core Reward Components

  • Distance Reward: Exponential function encouraging the end effector to approach the ball: dist_reward = 1.0 × exp(-1.6 × d)
  • Orientation Reward: Cosine similarity between end effector alignment and ball velocity direction, scaled by 0.4
  • Relative Velocity Reward: Encourages velocity alignment between end effector and ball using exponential weighting based on distance
  • Stability Reward: Penalizes ball velocity to maintain stable hovering phases: 1.3 / (1.0 + ball_velocity)
  • Target Distance Reward: Guides ball transport to target location with quadratic penalty: 1.0 / (1.0 + 5.0 × distance²)

Task-Specific Rewards

Rewards are modulated based on the current task phase to smooth transitions:

  • Catching Phase: dist_reward = 1.1, stability_reward = 1.1, emphasis on closing the distance
  • Stabilizing Phase: dist_reward = 1.3, stability_reward = 1.3, focus on damping oscillations
  • Stabilized Phase: dist_reward = 1.5, dist_to_target = 1.0, prepare for transport
  • Moving to Target: dist_to_target = 1.0, gravity_compensation = 2.0, emphasize target approach
  • At Target: dist_reward = 1.6, dist_to_target = 1.2, maximize stability at goal position
  • Throwing Phase: dist_reward = 1.6, throwing_pos_reward weighted by ball velocity magnitude

Penalty Terms

  • Revert Penalty: Applied when task transitions revert (e.g., dropped ball): -6.0 × velocity_factor
  • Joint Acceleration Penalty: Penalizes jerky movements: sum(joint_acceleration²)
  • Joint Jerk Penalty: Controls smoothness: sum(joint_jerk²)
  • Joint Torque Rate Penalty: Reduces actuator stress: sum(torque_rate²)
  • Action Sign Change Penalty: Encourages smooth action sequences: sum((sign(action_t) - sign(action_t-1))²)
  • DOF Limit Penalty: Applied when joints near limits: 1 point per joint exceeding 97% of range
  • DOF Velocity Limit Penalty: Penalizes excessive joint velocities
  • Termination Penalty: Large penalty (5.0) for trajectory boundary violations

Bonus Rewards

  • Task Completion Bonus: 5.0 awarded when transitioning to next task phase (one-time per phase)
  • Finished Episode Bonus: 400 awarded upon successful episode completion
  • Alive Reward: 0.3 baseline reward each step, boosted to 2.5 during final phases to encourage reaching conclusion
  • Gravity Compensation: Rewards end effector orientation aligned upward (preventing drooping)

Curriculum Learning Integration

The reward function incorporates curriculum progress to gradually increase task difficulty:

  • Bouncing Threshold: Decreases from 4.0 to 2.0 m/s as training progresses, making task harder
  • Velocity Factor: Dynamic scaling: 1.0 - (1.0 / (1.0 + 0.2 × rel_velocity²)) adjusts penalty magnitude
  • Penalty Scaling: Revert penalties increase with curriculum level to enforce better stability

Logging and Monitoring

All reward components are individually logged for analysis during training, enabling:

  • Identification of reward imbalances
  • Tracking convergence of each task phase
  • Debugging unexpected policy behavior
  • Visualization of learning progress per component

Design Philosophy: The reward function uses exponential and sigmoid-like functions to create smooth, continuous gradients that guide exploration without sharp discontinuities. Task-specific scaling ensures the agent focuses on the current objective while maintaining progress on fundamental skills like stability and smoothness.

Task Transition Logic

The system manages seven distinct task phases with automatic transitions based on state conditions. This ensures a smooth progression from catching to throwing while preventing premature advancement or regressive failures.

Task Phases

Phase Index Objective Primary Conditions
Catching Ball 0 Close distance and catch the object distance < 0.12m, rel_position < 1.5×radius
Stabilizing Ball 1 Dampen oscillations and stabilize distance < 0.12m, ball_vel < 0.3 m/s, rel_vel < 0.3 m/s
Stabilized Ball 2 Maintain stable state counter > 20 frames, stable conditions met
Moving to Target 3 Transport ball to target position stable && rel_vel < 0.3 m/s
Stabilized at Target 4 Stabilize at target location distance_to_target < 0.1m, all stability conditions
Throwing Ball 5 Execute throwing motion counter_at_target > 20 frames
Stop Manipulator 6 Hold final position ball_x > 0.2m, all velocities < 0.05 rad/s

Transition Conditions

Catching → Stabilizing: Triggered when ball is caught (distance < 0.12m and relative position within sphere). Reward: -4.0 × velocity_factor

Stabilizing ↔ Catching (Revert): Ball escapes stabilization when distance exceeds threshold or relative velocity too high. Bouncing threshold: 4.0 - 2.75 × curriculum_progress (decreases from 4.0 to 2.0 m/s). High bouncing flag triggers additional logging. Penalty: -6.0 × velocity_factor

Stabilizing → Stabilized: Three conditions must be met simultaneously: (1) distance < 0.12m, (2) ball velocity < 0.3 m/s, (3) relative velocity < 0.3 m/s. Counter increments each frame; reverts with -0.4 penalty if conditions break

Stabilized → Moving to Target: After 20+ frames of stability and relative velocity < 0.3 m/s. Enables horizontal transport phase

Moving → Stabilized at Target: Four conditions: (1) distance < 0.12m, (2) ball velocity < 0.3 m/s, (3) relative velocity < 0.3 m/s, (4) target distance < 0.1m. Counter_at_target increments when all met

Stabilized at Target → Throwing: After 20+ frames at target location. Automatically sets throwing_termination flag for trajectory tracking

Throwing → Stop: When ball x-position exceeds 0.2m (indicating successful throw). Episode ends when all joint velocities < 0.05 rad/s

Curriculum Progression

Difficulty increases as curriculum_level rises (0 to max_curriculum_level):

  • Bouncing Velocity Threshold: Linearly decreases, requiring better stabilization for higher levels
  • Penalty Scaling: 1.0 + curriculum_progress × 2.0 increases revert penalties
  • Effect: Early training focuses on basic catching; late training emphasizes minimal bouncing and smooth transitions

Counter-Based State Persistence

Two counters enforce minimum time in stable states:

  • stabilized_ball_counter: Must exceed 20 frames before moving to target (prevents premature transport)
  • stabilized_ball_counter_at_target: Must exceed 20 frames at target before throwing (ensures precise positioning)

Counters decrement by 1 if conditions are broken, gradually resetting if the policy loses control.

Episode Termination

Episode completes when two conditions are met:

  1. stop_manipulator flag is True (ball moved forward sufficiently)
  2. All robot joint velocities < 0.05 rad/s (manipulator fully stopped)

Successful completion awards 400 bonus reward and marks the episode as finished.

❓ Frequently Asked Questions

How long does training take?

Training typically takes 2-3 days on a high-end GPU for all tasks combined. Individual task training takes 4-6 hours each.

Can this work with other robots?

Yes, with modifications to the joint limits and kinematics. The code is modular and can be adapted to other 6+ DOF arms.

What's the real-world success rate?

Approximately 92% success on novel trajectories after sim-to-real transfer learning.
