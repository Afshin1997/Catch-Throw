🤖 Catch-Throw: Learning to Catch a Thrown Object

📄 Abstract 📥 Paper (PDF) ⭐ GitHub

Abstract

A key challenge in deep reinforcement learning for multi-task settings is performing long-horizon tasks consecutively and reaching the final goal through a single trained model. The objective of this research is to define multiple consecutive tasks for non-prehensile manipulation and achieve the final goal, which is hovering a thrown ball at a specific position. Separate but similar rewards are designed for each task to facilitate a smooth transition from one task to the next. The agents are trained in parallel with dynamic entropy levels, and the tasks are defined as catching, stabilizing, hovering, carrying to a target point, and hovering again. The results indicated that the agents can perform multiple tasks through one network for all the tasks and complete them consecutively to reach the final target point.

🎯 Contributions

  • ✅ Learning-based catching with non-prehensile manipulation
  • ✅ Sim-to-real transfer
  • ✅ Multi-task learning using a single neural network
  • ✅ Experimental validation on the KUKA iiwa robot
  • ✅ Reward design for smooth task transitions

🧠 Network Architecture

The policy network combines recurrent and feed-forward layers for temporal understanding and real-time decision making.

Architecture Details:

  • Actor Network: FC Layers: 44 → 256 → 128 → 64 → 7 units
  • Critic Network: FC Layers: 44 → 256 → 128 → 64 → 7 units
  • Normalizers embedded in the hidden layers of the Actor Network
  • Soft Sign function is considered as the activation function of the last layer of Actor Network

⚡ Entropy Scheduling

Dynamic entropy coefficient adjustment enables smooth transition from exploration to exploitation during training.

Schedule Details:

  • Initial entropy: 0.01
  • Final entropy: 0.002 - 0.004
  • Decay schedule: Linear over 10K episodes

🧠 Trained Models

This section showcases the different models trained throughout the development of the Catch-Throw system. Each model focuses on specific phases of the task, with videos, images, and descriptions explaining their performance.

Noisy Observation for Actor and Critic

Overview

Since the PPO algorithm includes two separate networks called the Actor and Critic Networks, they can be fed with different information about the environment and its states. More specifically, the Critic Network is fed with more information than the Actor one, but in practice for real hardware implementation, only the Actor network is used.

In this trained model, the Actor and Critic Networks are fed with the same level of noise, but the Critic Network is fed with more information about the environment and the state the agent is in.

Key Features:

  • This structure is mostly used in common PPO algorithms
  • Normalizers are embedded in the hidden layers of Actor Network

Noise Parameters:

  • Joint Velocities += U~[−0.03, 0.03] rad/s
  • Ball Position += U~[−0.01, 0.01] meter
  • Ball Velocity += U~[−0.1, 0.1] meter/sec
  • End Effector Position += U~[−0.005, 0.005] meter
  • End Effector Velocity += U~[−0.003, 0.003] meter/sec

Integrated RNN Network with MLP Actor-Critics

Overview

In this model, the network architecture incorporates recurrent layers that provide the agent with memory capabilities. Specifically, separate LSTM layers are placed before the Actor and Critic networks, enabling each to maintain its own temporal memory of past observations and experiences. The RNN layer maintains a hidden state vector that is updated at every timestep, creating a compressed representation of the agent's interaction history. When new observations arrive, the RNN processes them in the context of this historical memory, producing feature representations that capture both current information and relevant temporal patterns. These memory-enhanced features are then fed into the feedforward Actor and Critic MLPs for action selection and value estimation. The recurrent connections (self-loops) in each RNN cell enable information to persist across timesteps, with gating mechanisms (in LSTM) controlling what information to retain, update, or forget. This memory mechanism is particularly valuable in robotics applications where velocity estimation, dynamic adaptation, or multi-step coordination requires understanding of temporal context beyond instantaneous observations.

In this sectio the contributions are discussed.

🎯 Bounded Network Outputs

Overview

The entropy scheduler strategy provides the agent with bounds for maximum and minimum entropy at each step. If the variance of the action distribution decreases, the entropy value decreases, and while the variance of the action distribution increases, the entropy increases to encourage the agent toward higher exploration.

Bounded Network Outputs

Overview

Applying an activation function on the output of the network leads to have safer joint commands throughout the real world scenario implementation. More specifically this approaches is helpful in relative position commands rather than absolute positions commands.

Continual Incresing Reward

Overview

All the models are trained with a single network without explicit definition of sub-tasks in the observation state. More accurately, an innovation that is applied here is about feeding the networks with all the required data for specifying the sub-tasks, and forcing a single network (without any task differentiation like embeddings or one-hot encoders) to be trained based on those observations for all subtasks.

In other words, while Taskt = f(observation), we decided this f function be learnt by the network itself. However, it should be noticed that the rewards should be defined in an increasing pattern from stage to stage to encourage the agent to move forward toward the final sub-tasks.

Naturally, there are some challenges in this approach like catastrophic forgetting, but it is considered as future work to mitigate this issue for longer horizon tasks.

🧠 Safety Consideration

In this section, the safety functions considered in both simulation and hardware side are discussed.

Bounded Network Outputs

Overview

To avoid sending commands that exceed the feasible performance of the manipulator, a maximum fixed step size is defined so that at each time step, the joints can only rotate by a certain amount. For this specific manipulator, the maximum step size is considered to be 0.1 rad. It should be mentioned that this strategy only works when feeding joint commands as relative positions. When the joints are commanded using absolute joint positions, the safety is reduced.

Impose limitation on the workspace

Overview

By limiting the end effector workspace, when the end effector reaches the boundaries of that workspace, the manipulator is stopped suddenly. This unpredictable behavior is expected due to two deficiencies: 1- the ball is not thrown within the workspace of the manipulator, and in that case, by definition of the bounding box, the manipulator is stopped; 2- throughout the implementation and mitigation of sim-to-real challenges, in some cases the manipulator moved unpredictably due to various observation imperfections such as highly noisy data, which caused the manipulator to reach outside of that box. However, by definition of that box, the strange behaviors are limited to a high extent.

Applied Joint Limitation

Overview

Applying position and velocity joint limitations in both training and deployment enhances safety and prevents damage to the manipulator in real-world scenarios. This leads to avoiding high acceleration and jerky performance in real-world scenarios, and as soon as a single joint reaches its limit, the manipulator is stopped.

🔧 Technical Details

Learning Approach

We employed deep reinforcement learning with the following components:

  • Algorithm: Proximal Policy Optimization (PPO)
  • Network Architecture: 3-layer fully connected neural network
  • Actor Network State Space: 44-dimensional
  • Critic Network State Space: 102-dimensional
  • Action Space: 7-dimensional robot joint velocities
  • Training Time: ~20,000 episodes for all tasks

The observation space consists of 44 dimensions with carefully designed noise injection and scaling factors to improve sim-to-real transfer:

Reward Functions

THe reward function of all the stages are provided here. It should be mentioned there is no explicit stage definition for the network, but based on the observation data, the network should learn in whcih stage it is at each time state. Moreover, the rewards are defined in such a way to have higher basis reward at each stage more than previous stage to lead the network to have forward progression in completion of stages.

Core Reward Components

  • Distance Reward: Exponential function encouraging the end effector to approach the ball: dist_reward = 1.0 × exp(-1.6 × d)
  • Orientation Reward: Cosine similarity between end effector alignment and ball velocity direction, scaled by 0.4
  • Relative Velocity Reward: Encourages velocity alignment between end effector and ball using exponential weighting based on distance
  • Stability Reward: Penalizes ball velocity to maintain stable hovering phases: 1.3 / (1.0 + ball_velocity)
  • Target Distance Reward: Guides ball transport to target location with quadratic penalty: 1.0 / (1.0 + 5.0 × distance²)

Task-Specific Rewards

Rewards are modulated based on the current task phase to smooth transitions:

  • Catching Phase: dist_reward = 1.1, stability_reward = 1.1, emphasis on closing the distance
  • Stabilizing Phase: dist_reward = 1.3, stability_reward = 1.3, focus on damping oscillations
  • Stabilized Phase: dist_reward = 1.5, dist_to_target = 1.0, prepare for transport
  • Moving to Target: dist_to_target = 1.0, gravity_compensation = 2.0, emphasize target approach
  • At Target: dist_reward = 1.6, dist_to_target = 1.2, maximize stability at goal position
  • Throwing Phase: dist_reward = 1.6, throwing_pos_reward weighted by ball velocity magnitude

Penalty Terms

  • Revert Penalty: Applied when task transitions revert (e.g., dropped ball): -6.0 × velocity_factor
  • Joint Acceleration Penalty: Penalizes jerky movements: sum(joint_acceleration²)
  • Joint Jerk Penalty: Controls smoothness: sum(joint_jerk²)
  • Joint Torque Rate Penalty: Reduces actuator stress: sum(torque_rate²)
  • Action Sign Change Penalty: Encourages smooth action sequences: sum((sign(action_t) - sign(action_t-1))²)
  • DOF Limit Penalty: Applied when joints near limits: 1 point per joint exceeding 97% of range
  • DOF Velocity Limit Penalty: Penalizes excessive joint velocities
  • Termination Penalty: Large penalty (5.0) for trajectory boundary violations

Bonus Rewards

  • Task Completion Bonus: 5.0 awarded when transitioning to next task phase (one-time per phase)
  • Finished Episode Bonus: 400 awarded upon successful episode completion
  • Alive Reward: 0.3 baseline reward each step, boosted to 2.5 during final phases to encourage reaching conclusion
  • Gravity Compensation: Rewards end effector orientation aligned upward (preventing drooping)

Curriculum Learning Integration

The reward function incorporates curriculum progress to gradually increase task difficulty:

  • Bouncing Threshold: Decreases from 4.0 to 2.0 m/s as training progresses, making task harder
  • Velocity Factor: Dynamic scaling: 1.0 - (1.0 / (1.0 + 0.2 × rel_velocity²)) adjusts penalty magnitude
  • Penalty Scaling: Revert penalties increase with curriculum level to enforce better stability

Logging and Monitoring

All reward components are individually logged for analysis during training, enabling:

  • Identification of reward imbalances
  • Tracking convergence of each task phase
  • Debugging unexpected policy behavior
  • Visualization of learning progress per component

Design Philosophy: The reward function uses exponential and sigmoid-like functions to create smooth, continuous gradients that guide exploration without sharp discontinuities. Task-specific scaling ensures the agent focuses on the current objective while maintaining progress on fundamental skills like stability and smoothness.

⚠️ Challenges & Solutions

🔄 Challenge 1: Sim-to-Real Transfer Gap

The trained policy in simulation performed well but struggled when deployed on the real KUKA robot due to differences in physics simulation, sensor noise, and actuator dynamics.

✓ Solution: Implemented domain randomization during training, including random friction coefficients, object masses, and camera noise.

🎓 Challenge 2: Multi-Task Learning Convergence

Training a single network for seven consecutive tasks caused the network to forget earlier tasks (catastrophic forgetting) and struggle with smooth task transitions.

✓ Solution: Designed separate but complementary reward functions for each task with smooth transition criteria. Employed dynamic entropy coefficients to balance exploration and exploitation across tasks.

⚡ Challenge 3: Ball Tracking and Detection

The OptiTRack system required 10+ calibrated cameras and was sensitive to lighting conditions. Ball tracking sometimes failed when the object moved too fast or encountered occlusions.

✓ Solution: Applying Savitzky Golay and Moving Average filters for ball tracking and joint velocities estimation.

🤖 Challenge 4: Robot Safety and Hardware Constraints

The robot's joint limits, velocity constraints, and safety requirements sometimes conflicted with optimal catching trajectories, and hardware failures could occur during learning.

✓ Solution: Built safety constraints directly into the action space by clipping commanded target positions and enforcing joint limits. Trained exclusively in simulation with realistic constraints.
